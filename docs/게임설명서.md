## 2. 프로토콜 정의

### 2.1 공통 구조

모든 패킷은 `#pragma pack(1)` 적용, 첫 바이트가 패킷 전체 크기.

```
[1B size][enum type][payload...]
```

포트: **3500** (TCP)

## 3. 자료구조

### 3.1 오브젝트 계층

```
CObject (id, x, y, hp, max_hp, level, state)
├── SESSION  (소켓, recv버퍼, xp, inventory[6], quests[2], 버프 만료시각)
└── CNPC     (npc_type, target_id, spawn_x, spawn_y, active)
```

**전역 오브젝트 저장**: `tbb::concurrent_unordered_map<int, atomic<shared_ptr<CObject>>> clients`  
- ID 0 ~ 9,999: 플레이어  
- ID 10,000 ~ 209,999: NPC

---

### 3.4 섹터 시스템

```
섹터 크기 = VIEW_RANGE × 2 + 1 = 11 × 11
총 섹터 수 = ceil(2000/11) × ceil(2000/11) = 182 × 182 = 33,124개
```

각 섹터는 `unordered_set<int>`로 오브젝트 ID 관리.  
플레이어 이동 시 3×3 인접 섹터(최대 9개)에서 시야 계산.

### 3.5 DB 스키마

**Players 테이블**
```sql

x         SMALLINT

hp        SMALLINT
level     INT

inv1~inv6 INT          -- 인벤토리 슬롯 1~6 보유 수량
```


**저장 프로시저**

### 4.1 로그인 흐름

```
클라이언트                서버                       DB 스레드
    │                     │                            │
    ├─ C2S_LOGIN ────────>│                            │
    │                     ├─ CS_DB_WAIT 상태 전환      │
    │                     ├─ DB_LOGIN 이벤트 push ────>│

    │<── S2C_LOGIN_RESULT ┤
```

### 4.3 전투 흐름

**A키 공격 (4방향)**
```
C2S_ATTACK 수신
├─ 쿨타임 체크 (1,000ms)
├─ ATK 버프: dmg = 15 × 2 = 30, 기본: dmg = 15
├─ 상/하/좌/우 1칸 범위 내 NPC 전체 피격
├─ S2C_DAMAGE_INFO 브로드캐스트
├─ NPC HP == 0: npc_die()
│   ├─ 경험치 지급 (레벨²×2, Agro 2배)
│   ├─ 아이템 드롭 (확률 기반)
│   └─ 30초 후 EVENT_NPC_RESPAWN 예약
└─ 레벨업 체크 (while 루프로 연속 처리)
```

**S키 스킬 (3×3 광역)**
```
C2S_SKILL 수신
├─ 스킬 쿨타임 체크 (3,000ms)
├─ ATK 버프: dmg = 30 × 2 = 60, 기본: dmg = 30
└─ 플레이어 중심 ±1칸 정사각형 범위 내 전체 NPC 피격
```

**NPC 공격**
```
EVENT_NPC_MOVE 처리 중
├─ DEF 버프 활성: 실제 피해 = NPC_ATTACK_DMG / 2
└─ 기본: 실제 피해 = NPC_ATTACK_DMG (8)
```

### 4.4 사망 / 부활 흐름

**플레이어 사망**
```
HP <= 0 감지
├─ EXP 50% 감소
├─ 위치 = PC_SPAWN (1000, 100)
├─ HP = PC_MAX_HP 회복
└─ S2C_STAT_INFO, S2C_AVATAR_INFO 전송
```

**NPC 사망**
```
npc_die()
├─ 섹터에서 제거
├─ active = false
└─ timer_queue에 EVENT_NPC_RESPAWN (+30,000ms) 등록
   → 30초 후 랜덤 위치 부활, 섹터 재등록
```

### 4.5 아이템 흐름

**드롭**
```
NPC 사망 시
├─ Boss: HP포션 20%, Hi포션 20%, 엘릭서 30%
├─ Agro: HP포션 25%, Hi포션 10%
└─ Peace: HP포션 30%
→ g_world_items에 등록, S2C_ITEM_APPEAR 브로드캐스트
```

**획득 (자동)**
```
플레이어 이동 후 같은 타일에 아이템 존재 시
├─ m_inventory[slot]++
├─ S2C_ITEM_ADD (보유 수량 갱신)
└─ S2C_ITEM_REMOVE 브로드캐스트
```

**사용 (숫자키 1~6)**
```
C2S_USE_ITEM 수신
├─ 슬롯 유효성 검사
├─ HP 포션(1): HP + 30, 상한 max_hp
├─ Hi 포션(2): HP + 60, 상한 max_hp
├─ 엘릭서(3):  HP = max_hp
├─ 공격력 강화(4): m_atk_boost_until = now + 30초
├─ 방어력 강화(5): m_def_boost_until = now + 30초
├─ 이동속도 증가(6): m_spd_boost_until = now + 30초
└─ m_inventory[slot]--, S2C_ITEM_ADD 전송
```

## 5. 알고리즘

### 5.1 A* 길찾기

NPC가 장애물을 우회하여 플레이어를 추격할 때 사용.

```
탐색 범위: NPC-플레이어 바운딩박스 + MARGIN(20)
           → 최대 (AGRO_DETECT_RANGE + 20)² ≈ 900노드
휴리스틱:  맨해튼 거리
이동 방향: 4방향 (대각선 없음)
반환값:    현재 위치에서 다음 이동할 타일 좌표 1개
```

전체 경로 저장 없이 **첫 번째 스텝만 반환**하여 매 tick마다 재계산.  
경로 없음 → 현재 위치 반환(제자리).

---

### 5.2 NPC AI 상태 머신

```
IDLE ──────────────────────────────> ROAMING (Peace 없음 / Agro 랜덤 이동)
                                         │
                              플레이어 감지 (Chebyshev ≤ 10)
                                         │
                                      CHASE
                                         │
                              플레이어 이탈 (Chebyshev > 10)
                                         │
                                    IDLE/ROAMING
```

- **Peace**: 고정 (이동 없음)
- **Agro**: 스폰 위치 ±20 범위 로밍 → 플레이어 감지 시 A* 추격
- **Boss**: 감지 범위 15, 이동 간격 Phase별 차등 (P1=500ms, P2/P3=250ms)

---

### 5.3 보스 패턴 (3페이즈)

| 페이즈 | HP 조건 | 행동 | 데미지 |
|--------|---------|------|--------|
| Phase 1 | HP > 66% | 일반 근접 공격 (체비쇼프 ≤ 2) | 20 |
| Phase 2 | 33% < HP ≤ 66% | 빠른 이동 + 강타 | 30 |
| Phase 3 | HP ≤ 33% | 광역 공격 (반경 3) | 45 |

### 5.4 지형 장애물

`map.lua`에서 장애물 rect 목록 로드 → `g_obstacle_map[y][x]` 비트맵 변환.

```cpp
bool is_obstacle(int x, int y) {
    return g_obstacle_map[y][x];
}
```

Lua 스크립트 내용:
- 성채(castle) 100개+ 절차적 생성 (격자 step=140, 내부 공간 + 6칸 게이트)
- NPC 스폰 존 정의

---

### 5.5 섹터 기반 시야 관리

```
오브젝트 추가/이동 시:
  old_sector → new_sector 이전

시야 계산:
  플레이어 위치 기준 인접 3×3 섹터 내 오브젝트 조회
  → Chebyshev 거리 ≤ VIEW_RANGE(5) 필터
  → 이전 시야와 비교하여 ADD/REMOVE 패킷 전송
```

---

### 5.6 DB 비동기 처리

```
메인 스레드                    DB 스레드
    │                              │
    ├─ db_queue.push(DB_EVENT) ──>│
    │                              ├─ ODBC 실행
    │                              ├─ PostQueuedCompletionStatus
    │<── IO_DB_LOGIN IOCP 완료 ───┤
```

`concurrent_queue<DB_EVENT>`로 락 없이 생산자-소비자 패턴 구현.  
DB 스레드는 단일 스레드로 운영하여 DB 연결 1개 재사용.
